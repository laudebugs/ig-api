#Instagram Graph API — Agent Documentation Bundle

Generated: 2026-10-13 API base: https://graph.facebook.com/v25.0 or https://graph.instagram.com/v25.0 (set GRAPH_HOST/GRAPH_VERSION to match your Meta app; Meta's latest known is v26.0 — verify in Meta for Developers before shipping) Audience: coding agents and developers building apps that extend Instagram (publishing, insights, comments, messaging)

This bundle documents both Instagram API flavors: the Instagram Graph API via Facebook Login (Business/Creator accounts linked to a Facebook Page) and the Instagram API with Instagram Login (graph.instagram.com, no Page required). Start with the comprehensive reference: INSTAGRAM_GRAPH_API.md.

#How an agent should use this bundle

Three ways in — pick one, don't guess from prose:

  • Read whole: paste llms-full.txt (entire bundle, one file) into context, or read

INSTAGRAM_GRAPH_API.md (comprehensive narrative, curl + TypeScript + Python).

  • Retrieve slices: query data/chunks.jsonl (one JSON object per endpoint/topic) for RAG.
  • Generate a client: feed openapi.yaml (source of truth for paths/schemas) to your

OpenAPI codegen, with types/instagram-graph.d.ts for TypeScript shapes.

Then copy runnable flows from examples/ (TypeScript + Python), import postman/ or bruno/ to run requests by hand, and open site/index.html for the human-readable reference. Format rationale: FORMATS.md.

#Core concepts

  • Two flavors, one path shape: Facebook Login (graph.facebook.com, EAA… Page token, Page required) vs Instagram Login (graph.instagram.com, IGAA… user token, no Page). Never mix hosts/tokens.
  • IG User ID (ig-user-id): numeric ID of the Instagram Business/Creator account, obtained via the linked Facebook Page (instagram_business_account) or me on Instagram Login. Most paths hang off it.
  • Media container: publishing is two-step — POST /{ig-user-id}/media creates a container, POST /{ig-user-id}/media_publish publishes it.
  • Access token: Page access token (derived from a long-lived user token) authorizes most calls. Pass as ?access_token=... or Authorization: Bearer [REDACTED] (header preferred).
  • Permissions gate features: e.g. instagram_content_publish for publishing, instagram_manage_insights for insights. Missing permission → error 10 / 200 (see errors doc).

#Quick start

bash
export GRAPH_HOST=https://graph.facebook.com
export GRAPH_VERSION=v25.0
export IG_USER_ID=17841400008460056
export ACCESS_TOKEN=EAAB...

# Who am I?
curl -H "Authorization: Bearer ${ACCESS_TOKEN}" \
  "${GRAPH_HOST}/${GRAPH_VERSION}/${IG_USER_ID}?fields=id,username,media_count"

Full flows with responses: INSTAGRAM_GRAPH_API.md and examples/publish-photo.ts.

#Conventions

  • {version} = Graph API version (e.g. v25.0); {ig-user-id}, {media-id}, {comment-id} are numeric IDs (strings in JSON).
  • All examples use placeholder tokens/IDs. Never commit real tokens.
  • Dates in examples are illustrative. This bundle was generated 2026-10-13; re-check Meta changelogs for deprecations before relying on a version/metric.
  • Regenerate derived files after editing sources: python scripts/build-llms-full.py and python scripts/build-site.py.

#Deploying the site (GitHub Pages)

site/index.html deploys automatically via .github/workflows/pages.yml: push to main touching documentation sources rebuilds the site in CI and publishes it to GitHub Pages.

#Pull Request Previews

Pull requests automatically build and deploy preview sites via .github/workflows/pr-preview.yml:

  • Each PR is deployed to its own subpath: https://<owner>.github.io/<repo>/pr-preview/pr-<number>/
  • The workflow automatically leaves a comment on the PR with the live preview link and a QR code for mobile testing.
  • When the PR is closed or merged, its preview directory is automatically cleaned up.

#One-Time Setup

  • In GitHub: go to Settings → Pages → Source and select Deploy from a branch (Branch: gh-pages, folder: /).
  • In GitHub: go to Settings → Actions → General → Workflow permissions and select Read and write permissions (needed for PR preview branch commits and comments).
  • To preview locally: run python scripts/build-site.py and open site/index.html.
